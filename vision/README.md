# Velora Vision

Программа для компьютера в клубе: по просьбе клиента вырезает момент его
удара из записи камеры и отправляет видео клиенту через клубный бот.

**Для пользователя:** скачать `VeloraVision-windows.zip` из релиза
`vision-latest`, распаковать, открыть `VeloraVision.exe`. Инструкция лежит в
архиве (`README.txt`). Вводится только токен бота владельца и данные камеры,
для каждой камеры выбирается её стол.

## Как устроено

- Одна обычная программа с окном (tkinter), без Python и терминала у
  пользователя. Нарезку делает ffmpeg из пакета, никакого распознавания
  картинки нет (раньше программа считала людей у столов и ловила удары;
  это убрано как лишнее).
- Клуб определяется по токену бота владельца: функция
  `supabase/functions/vision-sessions` по токену отдаёт столы клуба, функция
  `vision-clips` выдаёт заявки клиентов и принимает готовый ролик.
- Настройки: `%APPDATA%\VeloraVision\settings.json` (токен и адреса камер
  зашифрованы DPAPI).

## «🎬 Мой удар» (ролик по просьбе клиента)

Клиент в клубном боте нажимает «🎬 Мой удар», выбирает стол и пишет время
(день выбирается в календаре, время пишется как `21:47`). Программа вырезает 30 секунд вокруг этого момента
из **записи самой камеры** (карта памяти или регистратор, как в SmartPSS Lite)
и сервер присылает ролик клиенту. Своя запись не ведётся, место на диске не
нужно.

- Видео берётся из **собственной записи программы** (`clips/local_record.py`):
  на каждый стол один ffmpeg копирует живой поток камеры (лёгкий `subtype=1`
  по умолчанию) без пережатия в куски по минуте `ГГГГММДД_ЧЧММСС.ts`, старше
  заданного срока (по умолчанию 24 часа) удаляются; клип режется из нужных
  кусков и сжимается до 720p. Нужна, потому что у базовых серий Dahua
  (например DH-IPC-HFW1639TC-A-IL) RTSP-архив отвечает 403, а веб-интерфейс
  ошибкой сервера.
- Если в собственной записи нужного времени нет, пробуется архив самой камеры:
  адрес `rtsp://…/cam/playback?channel=N&subtype=0&starttime=…&endtime=…`
  (из адреса живого потока `/cam/realmonitor`, время по часам камеры, которые
  программа спрашивает сама) и запись по HTTP (`/cgi-bin/playBack.cgi`)
  (`clips/archive.py`).
- Раз в 8 секунд программа спрашивает функцию `vision-clips`, нет ли заявок на
  её столы, и заодно сообщает, какие столы умеет резать: поэтому кнопка в боте
  появляется сама и пропадает, если компьютер выключен (`clips/client_clips.py`).
- Стол каждой камеры выбирается в её настройках (имя должно совпадать с
  названием в программе Velora Club). Камеры другой марки пропускаются.
- Кнопка «Проверить запись камеры» берёт несколько секунд из архива
  десятиминутной давности: так видно, что камера отдаёт запись.
- Кнопка «Изображение камеры…» (блик от лампы на столе): показывает настройки
  картинки камеры (`VideoInOptions`) как есть и ставит «Подавление бликов» (HLC),
  «Широкий диапазон» (WDR) или выключает компенсацию. Названия параметров у
  прошивок разные, поэтому значение пишется в том виде, в каком его отдала камера
  (число или слово), после записи читается обратно, а если камера не приняла —
  прежнее возвращается сразу. Исходное значение хранится в `camera_backup/`,
  «Вернуть прежние» возвращает его в любой момент (`camera_image.py`).
- Заявку принимает база (`bot_clip_request`): время не старше 60 дней (сколько записи хранит сама камера, зависит от карты памяти), не
  «только что», в это время за столом шла игра, не больше одной заявки в
  работе и 5 в час на клиента. Заявка, которую никто не взял за 10 минут,
  закрывается, клиенту приходит «не получилось».

## «Мой бот» и «📺 Онлайн» (личный бот владельца)

- Отдельный бот владельца (токен из @BotFather, НЕ бот клуба — тот работает на
  вебхуке, и опрос отсюда его бы сломал). Программа сама спрашивает Telegram
  (`getUpdates`), входящих портов нет (`personal_bot.py`).
- Привязка: окно показывает одноразовый код на 10 минут, кто его прислал — тот
  владелец (chat id в настройках). Остальным одна фраза, ничего не делается.
- Кнопки: фото (кадр OpenCV, сжатый лёгкий поток растягивается до 16:9), видео
  20 с живого потока (`cut_clip`), «минуту назад» из своей записи (`LocalRecording.cut`).
- «📺 Онлайн» (`live_view.py`): мини-приложение Telegram. Локальный сервер на
  127.0.0.1 + быстрый туннель Cloudflare (`cloudflared` лежит рядом с exe,
  иначе скачивается один раз; версия закреплена). Адрес туннеля меняется при
  перезапуске — кнопка меню у владельца обновляется сама (`setChatMenuButton`).
- Доступ: страница шлёт `initData`, сервер проверяет подпись Telegram токеном
  бота, свежесть (сутки) и что это владелец → ключ сессии на 12 ч. Без ключа
  картинки нет.
- Картинка — MJPEG (на странице запасной вариант — JPEG по одному, если поток
  встал). Камера читается только пока на неё смотрят, через 20 с без зрителей
  закрывается. Сетка: лёгкий поток 640 px, 2 к/с; на весь экран: 1024 px, 8 к/с;
  HD — основной поток, 1600 px.

## Разработка

    pip install -r requirements-dev.txt
    python -m pytest
    python app.py                    # окно из исходников
    python app.py --selftest         # проверка, что всё нужное на месте
    python scripts/build.py          # собрать dist/VeloraVision (PyInstaller)

Сборку под Windows делает `.github/workflows/vision-build.yml`: тесты,
упаковка, самопроверка упакованной программы, архив и релиз `vision-latest`.

Сторонние компоненты и лицензии: `THIRD_PARTY_NOTICES.md`.
